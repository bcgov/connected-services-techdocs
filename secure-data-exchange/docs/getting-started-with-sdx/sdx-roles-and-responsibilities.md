# P2P roles and responsibilities

## At a glance

**On this page:** The roles involved in setting up and managing organizations, systems and services within P2P.

**When to use it:** When identifying who needs to be involved in onboarding or understanding each role's responsibilities.

**Who is involved:** P2P operators, Organization Admins, System Admins, Subsystem Owners, Tech Leads and Access Managers.

## Roles and responsibilities

Different roles are responsible for setting up and managing an organization
within P2P. These roles help ensure that the right people have the appropriate
access to manage organizations, systems, and services. The table below provides
a high-level overview of the key P2P roles and their responsibilities.

!!! note "Organization and subsystem roles"
    System Admin is an organization-level role. Subsystem Owner is assigned
    to a specific subsystem and manages that subsystem and its related
    P2P resources.

| Role | Responsibility |
|---|---|
| P2P operator | Registers the organization in P2P and assigns its legal representative the initial Organization Admin role. |
| Organization Admin | Assigns System Admin access for the organization. |
| System Admin | Manages systems within the organization. |
| Subsystem Owner | Subsystem-level role for managing services for a subsystem. |
| Tech Lead | For service clients, request/revoke connections to another service. |
| Access Manager | For service providers, review and approve client connection requests. |

### During initial onboarding

The P2P operator completes the initial organization setup, including assigning
Organization Admin and System Admin access, in discussion with your
organization's representatives.

The role responsibilities above describe what each role can manage.
They do not mean that your Organization Admin must perform the technical
setup during onboarding.
