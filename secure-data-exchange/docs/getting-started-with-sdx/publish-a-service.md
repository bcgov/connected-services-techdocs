---
title: Publish a Service
---

Every provider organization must complete onboarding before publishing a service through SDX. See [Onboarding Process](#onboarding-process) to get started.

Once onboarding is complete, System Admins can publish services through SDX. The provider journey includes:

1. Complete organization onboarding – see [Onboarding Process](#onboarding-process)
2. Register systems and subsystems - see [Managing Subsystems](#managing-subsystems)
3. Register an API using an OpenAPI Specification (OAS) that meets the SDX API Standard requirements – see [Managing Services](#managing-services).

   - Note: review the [SDX API Standard Ruleset](https://developer.gov.bc.ca/docs/default/component/api-style-guides/sdx-style-guide/) before submitting your specification to understand the validation requirements your API must meet.

4. Provision and configure an SDX Edge Runtime Group – see [Install an Edge Runtime Group](#install-an-edge-runtime-group)
5. Publish the service to the service catalogue – see [Managing Services](#managing-services)
6. Enable secure data exchange with authorized consumers – see [Connecting a Service](#connecting-a-service)

Throughout this process, SDX applies encryption, authentication, policy enforcement, and audit logging.
